# 73帧舞段：根高与真实目标鞋底的离线分解

结论：`danceGroundLift`确实把整段额外抬高女性63.075mm、男性69.780mm，扩大了支撑悬空；但关闭或抵消这个常数也不构成修复。离线资产本身在197帧左鞋底低于虚拟地面64.094/70.653mm，而且部分双支撑区间左右鞋底不等高。需要显式人工支撑标注的有限根Y与腿/足适配，不能用失败自动contact结果或仅移动整段root。

范围仅源138–210共73帧（5.755750–8.758750s），不是30秒舞生产完成。原视频、raw点、v1/v2、runtime均未修改；没有GPU、浏览器、视频编码。图是实际目标几何的计算图，不是本轮角色视觉验收。

## 根高来源与运行时验证

每帧：`assetHipsY = restHipsY + source2DProjectedHipDeltaY + firstFramePlacementY`；后者为首次统一放置偏移F−48.669/M−53.401mm。鞋底则为`assetHipsY + poseRelativeSoleToHipsY`，其中已经包含固定目标骨长、模型方向及当前足姿fallback。运行时增加`danceGroundLift * danceMix`。

实际录制代码固定到`4958e6b60d8d97545b9332311958431aae0b20e2:prototype/src/motion.js`，SHA256 `01e7693c65d05cd40f7a7b4881c5b0a5c7c7066a1e7a55636f09fba4c0904a23`。本工作区现行文件不能替代该版本作为录制证据。

该实现取121个全段时刻，对实际鞋皮肤heel/toe低位patch做1mm指数权重soft-min，以全段最低点决定一个lift。脚在dance中不执行接触恢复。用锁定VRM、v2轨道和鞋蒙皮样本复算，lift与录制值误差F1.9e−15m/M1.3e−12m。实际trace中：asset与authored hipsY最大差<0.48µm；实际hips额外升高与L×mix最大差<0.026µm；实际踝与asset踝+L×mix最大差<1.57µm。这排除了本充分混合子集中毫米级的第二次normalized/retarget升高。trace未直接记鞋皮肤点，鞋底是精确资产/装备重放结果。

这些结果不证明源3D真实：MotionBERT没有米尺度实测地面。这里的“源资产穿地”特指离线目标适配结果，可能包含2D投影根高、预测腿方向及水平脚fallback的共同误差，不能把它归结为原真人或raw模型的物理穿地。

197属原观察的遮挡/身份不确定区，不能因此自动认定左脚真实支撑。全顶点最小值与121时刻patch soft-min不同，所以加lift后仍有约1mm负值，不能称精确零穿地。

171处原双脚已经近地，主要悬空来自全段抬升；153–164左前掌原本就高，女性中位63.19mm、男性69.25mm，lift后126.26/139.03mm。该处右鞋底原中位4.85/5.26mm，lift后67.93/75.04mm。错误不能全部推给runtime。

若给所有root键减常数c，重新标定会相反增加同一常数：`(assetY+c)+(L−c)=assetY+L`。所以把63/70mm简单减回导出轨会被现实现抵消。

## 支撑约束适用边界

人工13区间是显式清理输入的候选，不是假装自动检测或力板真值。只使用无unknown/or的明确支撑假设：138双脚、148–152右、153–164左前掌/右、171–176双脚pivot、200–205右；141–144和207–210保留腾空，其余保留未知/过渡。

同一rootY变化不改变两脚高度差。若原左/右接触面高为hL/hR，即使允许一脚穿地，最佳共同根高的最大绝对残差仍≥|hL−hR|/2；若还禁止穿地，悬空下界更大。153–164女性为27.73–32.68mm，男性30.29–35.86mm。171单帧仅0.89/1.01mm，而171–176区间最大18.21/19.94mm。是当前目标姿态与root-only相矛盾，不是证明人工两脚支撑观察自相矛盾。

保持当前踝XZ/足朝向，仅将选定接触面落地，使用实际大腿+小腿长的全伸直必要界：`deltaRootY <= desiredAnkleY + sqrt((thigh+calf)^2-horizontalDistance^2) - upperLegY`。153–164左脚最严格要求女性至少下降71.67mm、男性78.72mm；保持root不动会分别超腿长最多63.41/69.65mm。这只是必要界，不是成功IK解，还没考虑膝弯偏好/相碰/前掌roll。可选择足掌俯仰而不是让整条腿过伸，但当前数据没有真人足姿真值。

## 唯一下一步候选：人工支撑标注的有限清理

先保留以上冲突作为适用边界，不输出伪造的“只改root即成功”版本。建议一次独立派生候选，沿现有加载合同，不改runtime：

1. 单独保存上述人工支撑/前掌pivot/腾空/未知区间与来源SHA。前掌只约束前掌近地，不等于全脚平贴，也不做双脚XZ常驻锚。
2. 用少量连续分段根Y控制点及固定骨长两节腿IK联合拟合支撑高度，保留原rootXZ、原PTS、完整转体、上肢及v2前臂运输。脚掌俯仰仅作为明确fallback派生参数；不逐坏帧捏根高。使用一次固定目标/权重、一个固定迭代预算，失败保留，不扫参数。
3. 141–144、207–210原rootY/腿/足完整保护；其未加runtime lift的正鞋底间隙也须保留。未知区间不强设支撑；可施加虚拟地面非穿透不等式，但必须标成场景约束而不是识别出的接触。尤其197若完全保留原穿地，保守whole-lift将继续伤及已清理支撑，因此仅改known区间不够。
4. 输出有限根/腿/足修改量、每帧接触残差与不可达项；检查骨长不变、没有膝翻/异常速度、飞行保护、原XZ/转体/上肢不变。重新计算121采样lift及全部73帧鞋皮肤；评估应包含lift之后的接触残差。不要靠减常数伪造通过。
5. 若在保护腾空/骨长/转体条件下支撑或非穿透约束不可兼容，保留失败与最小冲突，不删跳跃、不改人形比例。仅数值可行后由root做正常1×男女实际回读；数值清理不等于动作合格。

该候选需要腿/足有限自由度，已经证明简单root-only不足；本诊断没有生成或覆盖新的角色动作。
