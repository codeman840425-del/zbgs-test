# 跑步减速回走路：错误支撑相位

失败固定版 `ca72ada827d2` 保留在 experiments/m1-ca72ada827d2/dist。原正常速度录像与逐帧记录在 output/playwright/m1/ca72ada827d2/runtime/m1c-runtime；此问题不能以平均FPS或纯跑步已通过排除。

## 已确认原因

女性基础/裤装在混合行程约5.28秒减速，Jog相位约0.2685/0.2700，左脚toe已超过18mm释放线，两脚均无接触。旧代码 `feet[0].contact ? .3 : .8` 把“左脚不支撑”误作“右脚支撑”，将walk选到相反半周。仅几毫秒偏差的女裙例仍有左脚接触，未触发同一错误；男例当时右脚确在支撑，也未触发。服装不是该动作错误的原因。

在0.30秒混合中，错误相位把左脚向前送过地面，脚底低于地面的中间姿势又被误识别为落脚。锚点保留在X约2.344m，角色继续前进，目标逐渐不可达。约5.55–6.40秒出现reachClamp；女性基础/裤装实际足踝目标最大残差分别310.8/316.5mm，后腿悬空拖在身后，直到停止收步才释放。

这不是原地walk循环首尾错误，也不是那一次男裤643ms浏览器帧间隔。后者重录48秒未复现（最大30.4ms、longtask零），原因仍不确定，保留原片与失败数据。

## 第二个已确认问题：收步时先升骨盆

ff91多相位检查消除了原拖腿，但发现0.3/0.8相位等停止时，第二只脚仍支撑等待第一只脚收拢，骨盆却已按idle上升。原几何可达计算只在moving/turning开启，在根速为零时失效。女B/P/S与男B/P复现116.7–258.3ms持续reachClamp，最大支撑误差约19.2/25.8mm。该失败保留，不因小于30mm支撑阈值而放行。

0df63cf2bdea把相同几何支撑计算延续至既有0.5秒收步窗口，仅实际contact脚参与；没有重设鞋目标、拉长转身、降低速度或缩小动作。骨盆只下降满足当前腿长所需距离，并沿既有阻尼恢复。同一固定阈值的五组合×六场景120Hz数值回归已通过；完整正常速度视觉仍另验，数值不替代视觉。结果与限制见 [独立回归记录](M1-LOCOMOTION-TRANSITIONS.md)。
