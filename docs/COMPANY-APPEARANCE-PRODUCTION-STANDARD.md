# 固定功能与可换外观生产标准

版本 1，2026-11-16。当前规格依据真实 `library-catalog.json` 中的 chair@1、lounge-sofa@1、desk@1，以及对应可编辑源和资源侧录。用户提供样式方向，agent 负责选材、制作、适配、导入、检查和失败恢复。

## 优先复用已有素材，再适配与组合

2026-11-17 用户补充素材来源后明确：开新素材包先查本项目已验库及官方免费素材，适用时优先复用并改造；缺少合适结构、状态部件或兼容造型时再制作。沿现有资源目录与 provenance 管理，不另建一套资产管理平台。提示词/设计输入同时允许“选用并适配已有资产”和“原创制作”，均须保留原始来源、修改内容和真实验收。

入库时记录官方包/资产 URL、取得时间、原包版本/哈希、许可证文件、修改/导出参数和衍生资源身份。固定单位/基点/轮廓接触/安装/状态规格及四款实检仍适用；缩放、重命名或改色不算新增外观。许可允许作为游戏使用，不直接证明所有独立素材交付用途都适用；按实际许可给既有打包流程登记可交付范围。

后续按家具承载、软装生活、主题直播、公共配套和饰面各包的现有范围选候选，先以少量真实源完成适配→运行→保存恢复，再复用同流程批量制作。当前制作包不因来源补充重启，已验证源码和证据保留。未验证本机 Blender MCP 或第三方导入插件可用，不将网上集成介绍写成本工程能力。

## 有限、版本化的规格库

每份制作输入同时绑定 targetProfileId、targetProfileVersion 和 designId。下表保留初始三项规格；屏幕、补光、桌面设备、装饰及建筑覆盖件的扩展规格沿资源侧录和可编辑 collection 输入登记。规格版本绑定确切来源与功能字段摘要。模型资源 ID、模型版本和造型设计 ID 分别保存。新增美术款式复用已有功能规格，功能参数变化须作为另一份明确规格审定。

| targetProfileId | targetProfileVersion | 实际参考 | 固定功能 |
| --- | --- | --- | --- |
| chair | 1 | library-catalog 的 chair@1 | 单人座椅，一个容量为 1 的使用点 |
| lounge-sofa | 1 | lounge-sofa/v1/resource.json | 双人沙发，left/right 各一个容量为 1 的使用点 |
| desk | 1 | library-catalog 的 desk@1 | 固定桌面承载区域与阻挡足迹 |

同一个 designId 可以按这三份规格分别生产。每个结果独立拥有资源身份、源参数、适配数据、检查结果和可重试状态。某一规格失败时保留其他成功结果，重试只针对该输入。统一设计可以改变轮廓、材质、纹理、构件和显示方式，每个规格仍需独立证明几何及接触适配。对同一个模型缩放后导出，仍需完成该规格的全部适配与检查。

角色生产同样沿有限、版本化身体规格组织。同款设计可分别适配男女各若干身材标准，数量由总工后续建议，用户尚未指定。骨架、蒙皮、表情和装备适配合同沿现有角色 M2 管理。本标准记录共用方法，具体角色标准及生产任务继续按角色工程授权执行。

## 功能字段

所有场景资源使用米制、Y 向上、局部 +Z 朝前，并在导入时烘焙到规定基点和单位缩放。运行时实例 ID、父节点、局部变换、工位归属、部件键和有效设备状态保持原值。

固定功能包括分类和功能角色、使用点 ID、容量、位置、朝向、座高、接近点、离开点、功能 clearance、阻挡 footprint、安装 mount、承载 surface，以及状态字段、类型和已声明状态语义。未来新增的使用点功能字段也参与比较。描述性的 limits、limitations 等文本保留在来源记录，换一种描述文字不会形成新的功能差异，数值限制仍参与比较。

可变显示数据包括网格、材质、贴图、外观材质槽和状态驱动的 mesh/light 映射。seatNodeId 和 backNodeId 是可变网格映射，使用点和接触区域仍固定。更换节点名称后，实际座面和靠背三角形必须适配原规定区域。纯静态 decor 若没有阻挡足迹、使用点、承载面、安装及状态功能，可以替换视觉身份。

`describeFacilityFunction(resource)` 输出独立功能描述。`compareFacilityFunction(source,replacement)` 返回 compatible 和 differences，每个差异含资源相对 field 路径及前后值。元数据比较不执行模型导入，也不证明网格接触。

## 当前实际尺寸

### 单人 chair@1

基点为地面中心，阻挡 footprint 的 center 为 `[0,0]`，halfSize 为 `[0.275,0.255]`，完整范围为 0.55 × 0.51 米。状态字段为空，地面安装。

| 字段 | 固定值 |
| --- | --- |
| 使用点 ID 与容量 | seat，1 |
| position | `[0,0,0]` |
| yaw | `0` |
| seatHeight | `0.47` 米 |
| approach | `[0,0,0.6]` |
| exit | `[0,0,0.65]` |
| clearance | width `0.7`，depth `0.65` 米 |
| 原始显示映射 | chair-seat、chair-back |

新座椅可采用独立的座面和靠背节点名。agent 应从原参考源确认接触面，再检查新网格在固定座高、坐点和靠背接触区域内的实际三角形与法线。使用点坐标不会随扶手或靠背造型移动。

### 双人 lounge-sofa@1

阻挡 footprint 的 center 为 `[0,0]`，halfSize 的原始数值为 `[1.100000023841858,0.5199999809265137]`。可读尺寸约为 2.20 × 1.04 米，机器输入保留原侧录的完整数值。总容量为 2，两席各自拥有独立 ID 和容量 1。状态字段为空，地面安装。

| 字段 | left | right |
| --- | --- | --- |
| position | `[-0.48,0,0.04]` | `[0.48,0,0.04]` |
| yaw | `0` | `0` |
| seatHeight | `0.47` | `0.47` |
| capacity | `1` | `1` |
| approach | `[-0.48,0,1.02]` | `[0.48,0,1.02]` |
| exit | `[-0.48,0,1.15]` | `[0.48,0,1.15]` |
| clearance | width `0.92`，depth `1.11` | width `0.92`，depth `1.11` |
| 原始显示映射 | seat-left、back-left | seat-right、back-right |

当前源参数的每席座面宽 0.92 米、深 0.74 米，中心 Z 为 0.04 米。已制木框样件沿用靠背接触锚点 `[±0.48,0.72,-0.30]`，靠背倾斜后通过离线平移，使真实前表面仍经过该锚点。生产检查读取导出后的三角形，对座顶和背面做接触射线与区域采样，同时检查扶手、支撑、实际外包络和足迹。

lounge-sofa@2 的原始 halfSize X 为 `1.1599999994039536`，其阻挡功能与本规格不同。原资源及旧布局继续按原义读取，新换外观操作拒绝 lounge-sofa@1→@2。先前 C1 证据保留历史身份。timber-sofa@1 复用 lounge-sofa@1 的完整功能，具有独立木框、立柱、薄坐垫和倾斜背板，可作为该规格的新外观。

### 桌面承载 desk@1

surface.topY 为 `0.84` 米，surface.halfSize 为 `[1,0.5]`。阻挡 footprint 的 center 为 `[0,0]`，halfSize 为 `[1,0.5]`，完整足迹为 2 × 1 米。桌面装置的 mount 为 desk-surface，装置原点须落在该承载平面和横向范围内。桌面设备的状态字段和功能角色保持原规格，屏幕、按键、灯光和材质的显示映射可以独立适配。

## 统一制作提示词模板

每次填写同一模板，固定部分来自版本化规格和来源文件，造型部分来自同一个 designId。批量生产时对 targetProfiles 逐项展开，每项绑定自己的来源摘要、预算、适配和输出身份。

```text
为公司场景制作一份可运行 3D 外观资源。

本次 designId 为 {{designId}}。
造型方向为 {{styleDirection}}。
当前目标为 {{targetProfileId}}，规格版本为 {{targetProfileVersion}}。
本批其他目标规格为 {{targetProfiles}}，保持同款设计的材质和造型语言。

固定规格全文为 {{fixedFunctionJson}}。
规格来源与 SHA256 为 {{profileSourceAndDigest}}。
参考源、当前接触区域、网格映射和限制为 {{referenceAndContactData}}。
资产预算与许可约束为 {{budgetAndLicenseRules}}。
本项输出身份及版本为 {{outputResourceIdAndVersion}}。

按固定规格独立制作和适配本项几何，保持使用点 ID、位置、yaw、容量、
座高、接近和离开点、clearance、footprint、mount、surface 与状态语义。
可调整轮廓、构件、材质、纹理和显示节点映射。
座面和靠背实际三角形须覆盖原固定接触区域，法线与用途相符。
保留规定基点、坐标轴和单位缩放，完成离线适配后导出。

输出可编辑源、参数、来源与许可、资源版本、GLB、资源侧录、网格映射、
材质槽和检查结果。记录实际生成工具及版本、全部输入和输出摘要。
本项完成实际导入和功能比较，检查网格、接触、安装面与外包络。
某项失败时说明具体规格、字段、输入版本及恢复方式，保留其他成功结果。
```

生成图片可以作为造型参考。可运行的 3D 结果仍需完成正常建模或生成、离线适配、GLB 导出和实际导入。提示词记录设计输入，检查结果由真实产物及运行证据产生。

## 生产与导入实检

2026-11-16 数量验收补充：按用户最新要求，每个已经确认的可替换外观细分分支至少四款，完成实际替换、身份/功能保持、状态（适用时）、保存及关闭重开。只改色、同件复制、改 ID 或版本、不能兼容原规格的尺寸变化均不计数。单人/组合工位和其中的椅子/屏幕等分属多个分类标签时，复用同一套四款实际成果并逐项记录，不复制文件凑数。通路、区域连接、镜头是机制，不另造四套逻辑。

建筑覆盖件的 mounting 尺寸、安装面、原点和净开口属于固定功能合同；实际导入检查显示包络。地板/地毯贴原地面，墙板/挂画/窗饰贴真实室内墙面，不允许覆盖门户；开放门框必须对齐既有门口并保持净宽。门框未实现开关门，窗饰未实现开合或真实窗洞。观看剖切只作用于显示，碰撞、门户及逻辑实例不随之变化。

实际 GLB 屏幕及补光发光面使用 display.screen 映射（nodes、onColor、offColor、emissive、onIntensity）；开关仍消费既有 on 状态。补光同时沿 light 配置创建实际 SpotLight，不能用发光材质冒充照明。几何源为可编辑构造与参数，属于技术造型样件，最终美术观感仍由用户观看确认。

1. 固定参考规格及 designId，记录精确来源版本、源文件、许可证和输入摘要。检查源、参数和输出身份互相对应。
2. agent 制作每份独立模型与适配数据，保留可编辑源。实际几何可以明显不同，功能区域与坐标保持固定。
3. 导出 GLB 并由锁定导入器回读，核对文件 SHA、网格、单位、材质槽和资源映射，检查外部依赖及可重复构建。按对应资产规范验证网格预算和源许可。
4. 比较全部功能字段，再检查实际座顶、靠背接触面、承载平面和阻挡包络。相同名称、相同容量和元数据相等各自提供有限证据，实际网格仍需检查。
5. 通过共用场景链加载完整候选，检查外观、安装、灯光及资源清理。保存旧布局和状态，任何失败均保留原场景与存档。新的实例身份沿既有实例合同创建。
6. 在 C3 的固定候选中验证真实男女接近、使用、离开、接触、争用和恢复。CPU 静态检查与先前样件接触记录分别保留各自覆盖范围。

外观替换先比较固定功能，成功时保留原 effective 设备状态，再切换资源引用。显式模板升级复用同一功能比较，若目标资源或 part.state 默认会改变已有状态，则按具体字段拒绝。agent 可在独立候选中明确保留旧有效状态后重新准备升级，最终只发布完整通过的候选。

本标准直接沿既有资源、参数、导出脚本、共用加载、prepare 和保存入口执行。人类预览呈现造型、规格身份、版本和限制，专业适配与输入修复由 agent 完成。
