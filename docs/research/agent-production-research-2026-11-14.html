01　结论与本轮范围

当前主路线继续采用：现有可编辑基模 + Blender 脚本制作与编辑 + 游戏中验证。

简单附件、基础服装和短手势由 Codex 直接制作；人物外观在已验证基模上做受限派生；完整拟人舞蹈优先采用合适源动作，经编辑、重定向和接触修正后交付。暂不因新工具宣传更换引擎或基模。

这是第一批资料核查与本地文件盘点，不是美术验收。没有改动 F:/gamemake、运行其构建或导出脚本，也没有调用付费生成接口、注册账号或上传项目模型。项目仍在开发，本文中的状态仅对应本次观察；实际通过状态仍由工程 CAPABILITIES.md 管理。

报告区分三类依据：本轮直接检查文件、哈希、GLB 头与动画时间范围；工程记录已有生成和验证报告，未在本轮重复执行；官方资料／工程建议工具文档确认的能力及本报告据此提出的选择。

03　角色与服饰：按资源类型选择生产方法

资源建议生产方式交付边界与重点
脸型／局部体型在当前基模上，用版本化参数与几何变形生成派生资产；保留原件。先验证有限范围；脸部要复查眼牙、闭眼和口型。对所有形态键加同一位移能保留数值差值，但不自动保证极端脸型的视觉正确。
基础上衣／裤子以完整身体或独立版型为参照生成裁片、厚度、边缘和 UV，再建立蒙皮。身体表面的复制适合部分贴身结构；宽松轮廓、领袖、开口和叠穿需要专门版型，不能全部靠沿法线外扩。
裙子／外套独立轮廓与拓扑 + 骨骼蒙皮／必要修正形态；按预算加入附加动态。体型适配、关节变形、布料摆动是不同问题。静止贴合通过不能证明坐下或舞蹈通过；不承诺通用布料物理。
麦克风／眼镜／简单饰品曲线、基本体和尺寸参数生成；保存语义挂点与基模适配数据。最适合先证明直接自制流程。可编辑源、实际比例、独立对象与安装姿态必须保留。
发型／复杂装饰独立发束或网格模板、UV 与材质，再配置权重／附加骨。需处理头围、发际线、帽子关系和动态成本。先一件样品；不承诺一句描述即可稳定产生任意精细发型。
纹理／材质变化基于稳定 UV 生成颜色、图案或贴图变化，保留分层源与材质参数。纹理变化不能代替新服装轮廓；Blender 预览须与浏览器材质对照。

Blender 与 VRM 插件提供 Python 导入、编辑和导出入口，能够组成 Agent 可重复执行的制作流程；glTF 导出能保存蒙皮、形态键和支持的动画。导出能力不等于所有 Blender 材质、修改器或模拟行为都自动进入游戏。[S1] [S2] [S3]

保留三个有明确用途的方案

方案证据与优势本轮决定
现有 Blender + VRM 制作脚本工程锁定 Blender 4.5.9 LTS、VRM 插件 4.10.5；已有可编辑基模、几何派生、裤装和附件。继续作为主路线。先完成现有样件的实际接入和视觉验证。
MPFB / MakeHuman官方提供体型与服装映射／重新贴合机制，包含权重转移与遮挡数据；核心资产和代码的许可分别管理。[S4] [S5]保留为方法与工具备选。它依赖 MakeHuman 基模映射，不是给当前 VRM 任意衣服直接套用的按钮；目标二次元画风与现有工程适配尚未实测。
生成式 3D 工具，以 Meshy 为调查样本官方 API 提供人体绑定；官方说明自定义面部等骨架仍需 DCC 工具处理。[S12] [S13]暂不作为统一人物母体来源。可考虑独立道具／外形试制；一致拓扑、完整隐蔽身体、表情、换装分层和预算均需另外验证。本轮未调用。

旧 VRoid New model 有官方 CC0 页面；当前 Studio 对内容和角色生成应用另有约定。现有候选来自第三方旧版导出，工程尚未完成与官方原始导出的身份核对。继续保留这一待核事项；新增发型、服装与纹理须独立记录来源，不沿用一个笼统的“VRoid 可商用”标签。[S6] [S7]

04　舞蹈与直播动作：直接制作与编辑结合

动作类型主方法最小验证
挥手／点头／持麦姿态Codex 制作关键姿态、曲线与过渡，导出可编辑动作。利用 M1C 已计划的一个手势；检查准备、动作、收回，以及手臂／手指与持物通道。
站姿／坐姿讲话先编辑已有 Talking 源，按声明范围控制上身；眨眼、口型、视线独立合成。不能仅删除腿部轨道却保留会带动腿的髋部运动；保留坐稳与脚底条件。口型试验不代表音频驱动讲话已经完成。
走／普通跑筛选合适源，或离线编辑形成明确命名的派生动作，保留原源。以目标角色实际足轨、步频、支撑和腾空验证速度。新普通跑派生已有文件，直接复用其待验流程。
完整舞蹈源动作／动捕数据 → 编辑与重定向 → 根运动和接触修正 → 游戏验收。在现有 M1C 少量样件范围内区分技术压力动作与正式表演样片；正常速度检查重心、连贯性和节奏。

现有 M1C 源报告已经发现：动作名为 Jog，并不保证在目标角色上适合普通慢跑；仅换速度数字也无法保证脚不滑。这里应继续现有源轨迹分析与派生编辑，不重新把“包里有 Jog”当成完成证据。

动作来源与生成工具的调查结果

候选已核实内容选择与限制
Quaternius UAL官方标 CC0，Source 层含 .blend。当前本地 UAL1 是 43 段，Dance_Loop 仅 1 秒。[S8]继续用于基础动作和编辑起点。免费包、整套产品、源工程层和完整舞蹈数量分别核查；本轮不建议为数量直接升级。
KayKit Character Animations作者提供 CC0 动作，含模拟类手势；FBX/glTF 可取得，.blend 源为另一个版本层。工程报告已取得 Free 包。[S9]作为手势／动作备选。其人物比例不同，源筛选已经暴露普通跑不直接适用，需目标骨架验证；不重复下载已有包。
MixamoAdobe FAQ 说明需 Adobe ID，可用于包括游戏在内的商业项目，并列出账号类型／地区限制。[S10]条件备选。本轮未登录、未取得具体舞蹈。账号可用性、实际片段、浏览器分发条件与自动化方式仍须核实，不作为唯一供应。
Meshy Text to Motion官方接口生成独立动作；prime 输出 FBX、swift 输出 BVH；时长 2–10 秒，需付费计划。本次页面列每次 10／3 credits。[S11]只作为短动作试制候选。未调用、未验证自然度、当前账号价格与具体输出许可未准入；它不能据文档就被称为整首舞蹈生成方案。
Rokoko Create官方提供视频／文字动作生成，经 Studio 编辑后导出，并说明生成动作可商用。[S14]动捕／长动作来源研究候选。输入素材条件、实际可生成时长、订阅费用和 Agent 自动化流程未实测。本轮未上传视频或注册服务。

VRMA 可以表达 humanoid 骨骼、表情与视线；它解决交换格式的一部分，不会自动修好不同身材、衣服和地面接触。先保留已能工作的 GLB 流程，有实际来源需要时再验证 VRMA 转换，避免同时实现所有格式。[S15]

采购结论：本轮没有发现“必须立即付费才能继续”的证据。先用已取得资源和已生成样件完成验收；需要付费试验时，再给出具体样件、费用上限和成功标准。

05　同一套生产验收，不再扩出新里程碑

复用现有样件要证明的生产能力完成标准
下颌／腰臀两个派生改源以后能重新生成真实外观变化，并追溯版本。在对应基模实际加载；脸部表情与代表走坐链通过；适配限制单列。男性需要独立核查，不能继承。
已有男装或变体裤装由参数与源文件重建装备，精确匹配主体。新装备 ID／绑定数据／覆盖区域正确；相同动作控制可复用，特殊修正保留为资源配置。
已有麦克风／眼镜从自制几何到装备挂点和行为组合。男女分别标定；持麦站讲、走路、坐讲和卸下恢复；所有权不串用。
M1C 一个手势Agent 能直接制作并编辑短动作。有可编辑源、明确开始结束和过渡；原速可看，手指／持物无明显冲突。
已有技术舞 + 计划中的代表舞测试覆盖和实际表演品质分别成立；新动作可持续进入管线。技术舞保留为测试资产；正式样片需有源、版本、根运动／接触声明和正常速度视频。拼接重复不能自动充当新编舞质量。

每次交付保留：可编辑源、生成／修改参数与脚本、工具版本、来源与使用条件、运行资产、兼容范围、验证视频。记录一次新增样件实际需要的 Agent 操作、返修次数和外部费用；当前没有足够数据给出可靠批量工时或成功率，不编造估价。

通用流程固定：定义样件与目标 → 制作或选源 → 编辑 → 离线检查 → 导出／转换 → 游戏实际运行 → 视觉复核 → 归档。资产只因文件生成而进入“待验”，通过状态必须绑定实际组合。

07　经营玩法：首版研究假设

这一页用于后续讨论，不作为本轮 M1 开发任务，也不代表已经证明好玩。参考范围：Idol Manager 的人才／公司管理，Youtubers Life 2 的内容选择／趋势与粉丝成长；两者的整套规模不照搬。[S16] [S17]

候选循环：选择主播 → 安排直播内容和时段 → 获得资金与粉丝反馈 → 培训、休息和设备投入 → 调整下一次安排。

  • 首版用资金、粉丝、技能、精力四类状态研究策略，暂不堆叠多种货币。
  • 主播差异先落在内容适性与培养选择。外观、舞蹈和服装对收益是否有影响，属于待确认产品规则，不能由美术稀有度自动决定。
  • 离线计算以业务时间和已确认任务为依据。回访时呈现结果与新的可选安排；不要求动画一直运行。
  • 后续先做单公司完整经营链，再按实际设计接榜单、交易和异步 PK；现在不要求服务器实现。
  • 下一次产品判断应看可点击的短流程或数值演示：是否有真正需要选择的事情、不同选择是否产生可理解差异、投入能否支撑新的选择。当前不承诺具体留存或收益。
