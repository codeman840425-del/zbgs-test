# 座椅声明与实际坐面的交付检查

本检查供场景制作者和角色接收方使用。现有固定单椅和双人沙发的声明座高均为 0.47 m。角色接缝通过每个稳定使用点取得进出位置、座高和实际接触网格。这里测量场景提供的坐面。人物骨盆、衣物厚度、坐起动作、占用及身体适配由角色侧在固定集成候选上验证。

## 从新配方批量生产

创建房间时，在规模输入中指定 `furnishingVersion: 2`。缺省工位选用 `stream-station@3`，其座椅为 `chair-ladder@1`；独立房间内的 `desk-chair` 也使用同款椅。显式指定的旧工位版本或设施引用继续有效。历史批次省略家具版本时沿用原来的选择。两间样房的可编辑输入在 `scripts/company-platform/batch-inputs/seat-contact-rooms.json`。

## 制作与检查

在安装了锁定依赖的源码工作副本中运行下列命令。可一次传多份布局或存档，报告选用新的文件名。

```powershell
node scripts/company-platform/check-seat-contacts.mjs 房间一/save.json 房间二/save.json --report 座面检查.json
```

工具核对存档里绑定的目录与版本，逐层找到每个声明座面的使用点，将真实程序网格或登记 GLB 按实例和使用点的世界位置与朝向布置。游戏接触接口保留完整的公司、配桌等归属关系，并分别取得各坐点的实际网格。在指定坐面的中心及前后左右各 2 cm 处，分别自上向下与实际三角形求交。每处最高命中须有朝上的表面，所得高度相对设施原点与声明值相差最多 0.000001 m。此数值沿用固定平坐面生产检查的浮点精度，适用于该类坐面几何。若以后制作弯曲或多区承重的坐面，须先定义对应的接触区及预期高度。

报告列出公司、楼层、设施 ID、资源版本、使用点、声明与实测值、各采样坐标和失败原因。未显示楼层同样参与。没有声明坐面的场景计为零个使用点。错误退出码为 1。文件格式、资源哈希和接触面的实际几何均须符合要求。

## 交给角色集成

打包时在既有命令上加 `--seat-contacts`。默认房间及每一个 `--room` 存档都通过后才发布，逐房结果写入 `data/seat-contacts.json` 与 `data/rooms/<房间名>/seat-contacts.json`，清单索引为 `seatContactReports`。某一使用点失败时错误给出房间路径、点 ID 和实测信息，并保留已有包。用于复现历史问题的包保持原始功能和原始字节。

## 旧装修的显式修正

原程序资源 `chair@1` 的坐面中心为 0.44 m，网格厚度 0.07 m，顶面为 0.475 m；其声明值为 0.47 m。原始设施提取工具曾记录这项限制。已有四款单椅 `chair-ladder@1`、`chair-cantilever@1`、`chair-pedestal@1`、`chair-crossbeam@1` 实测均在声明高度。它们是四种独立造型。

旧存档使用精确资源和模板版本。要换成梯背椅，请在接收方工作副本用 `edit.mjs apply` 将以下操作应用到原存档，输出到新目录。批量处理时为各实际椅子分别提供其稳定实例 ID。

```json
[{"type":"replace-resource","id":"screen-partition-studio/ground/live/station-left/chair","resource":{"id":"chair-ladder","version":1}}]
```

该操作保留实例 ID、工位归属、坐点、朝向与进出位置，新的存档绑定替换后的造型。已有自定义材质须显式适配新材质槽；忙碌设施继续遵守原有占用保护。沙发若换款涉及更大的脚印或新的承载面，应走重新布置操作。保留原文件便可复现旧房；在同源浏览器主动保存同一公司会更新其现有存档键。

## 化妆桌专属侧入座椅

`vanity-chair-side-entry@2` 沿用旧款的化妆桌配对、侧向接近点和离开点，显示资源采用已测梯背椅。旧 `@1` 的座面仍比声明高 5 mm。需要修正时把旧座椅原位显式换成同 ID 的 `@2`。普通梯背椅与专用侧入椅的使用点约定不同，应按实际用途选择。
