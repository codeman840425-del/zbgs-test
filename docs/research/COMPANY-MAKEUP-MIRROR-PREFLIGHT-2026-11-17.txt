四、实体支承、四款结构与有限反射面

共同底座候选为 .24×.03×.14m 完整闭合实体，X[-.12,.12]、Y[0,.03]、Z[-.07,.07]。共同柱 X[-.025,.025]、Y[.03,.24]、Z[-.035,.005]，与底座正面积面接触。各款指定厚背板必须从 Y≤.24 开始，在该柱的真实内部有正体积相交，不能只用圆背板 AABB 与柱重叠作为连接证明。框、灯罩、灯支架及侧翼的每个闭合实体须连接到指定背板/柱/底座网络。底座完整底面在 Y=0 接触父桌面，所有部件在 .70×.60×.16 包络内。

中央镜面候选为竖直 +Z 平面 Z=0，基准点 [0,.365,0]，面轮廓顶点在各自声明范围内并烘入 Float32。背板可占 Z[-.025,-.009]，镜前框沿轮廓外围布置，灯罩与前框不得遮入任何声明镜片内部。中央反射头部轮廓约 Y[.18,.55]，全结构最高 .60。此与旧 wall/floor 的 z=.026 明确分支化，不改旧资源语义。

圆镜采用真实圆片，候选直径 .36m、圆心 [0,.365]，背板/环框有厚度，支柱实际接入圆背板下部。带灯镜采用独立矩形镜体和更宽的实体灯框/扩散条，中央片候选 .40×.36m，不能仅给圆镜改颜色凑一款。拱镜采用实际弧顶轮廓及相应厚背板/框，中央头部底 .18、顶 .55m，框体有真实拱形外缘。四款共享安装、补光输出和最大活动反射面数，实际镜片轮廓继续作为外观适配核验。

三折镜需真实三面结构。建议固定展开姿态，中央片宽 .28m、高 .37m，左右翼各宽 .14m、高 .37m，围绕 Y 轴向前折 30°，通过真实厚铰接柱/背部支架连接中央背板。左翼绕 X=-.14 的竖边转 +π/6，右翼绕 X=.14 的竖边转 -π/6。侧翼前探约 .07m，外半宽约 .14+.14*cos(π/6)=.2613m，加入 .01m 框/厚度仍能落在半深 .08/半宽 .35 候选内，但必须按实际三角及转角精确核包络。固定铰接造型不声明开合状态或可变折角。

一个 Reflector 的同一投影不能正确覆盖这三个不同法向的镜面。建议新台镜允许 1–3 个真实平面适配条目，每个条目包含稳定 face key、面/背/框节点、固定 plane position/yaw 与其平面内轮廓。每面分别建立现有 Reflector binding 候选，所有候选仍交同一控制器，整个宿主当前最多一个活动目标和一次反射。三折镜左右翼分别实际激活过才有对应反射证据。非活动面按现有受限表面处理并明确显示预算限制。

这需要主代理在新合同中决定是否采用该有界多面适配。若只做中央镜片实时、两翼永不具备真实反射候选，必须标明其限制并由主代理确定是否满足本确认分支，不能用共面分格镜改名顶替三折镜。本预检推荐 1–3 面候选共享一目标，保留三折真实结构与每面正确反射机会。

五、反射器最小扩展方案

资源层为 makeup-mirror 单独定义受限 schema 和几何配置，固定安装包络、support-surface、最多 3 面/全宿主最多 1 面活动、默认 single-512-v1、灯光及状态。旧 wall/floor 路径保留原严格字段和值。可使用独立 makeup-mirror-data.js，或在 mirror-data.js 入口分派专用校验，避免放宽 wall/floor 的边界来接受新资源。

几何层抽出当前已核的有限平面、轮廓覆盖、厚背板、遮挡检查所用 profile 参数，旧 profile 仍给原尺寸和 z=.026。新台镜每个面先把实际资源空间顶点投到声明平面的局部基底，再运行同一共面/+Z/覆盖算法。资源整体包络始终在资源空间核对。底座/柱与背板、侧翼框、灯支承的逐实体连接沿现有闭合实体方法复用，有界参数必须实际检查，不能凭节点名称过门。

绑定层可继续复用 createMirrorBinding 的单面生命周期，把新资源的一个面描述归一成单绑定输入。对烘入资源坐标的侧翼，clone 后用该面 transform 的 inverse 变换到 Z=0，再将 Reflector 放回该 transform。父台/设施 root 的最终世界变换仍由 Object3D 共用。当前 eligible() 的法向取父节点 +Z，且镜片/Reflector 假定无局部 rotation，侧翼扩展时必须改为每面基底组合出的真实世界平面点和法向。不能只改允许位置就把侧翼当中央平面。

render.js 当前 facility.mirror 为单 owner，镜片枚举、disposeTree、preflight、profile 切换、mirrorBindings() 和统计均以单绑定为单位。新台镜可提供 owner 集合并在枚举时 flatMap，或提供一个拥有 1–3 子绑定的 facility owner，统一幂等释放。不能只把第三面绑定加入 scene 而漏掉预热/销毁/候选回收。全宿主 controller 仍唯一，不给化妆镜新增控制器或常驻目标。

当前 choose() 按绑定 id 排序后取首个可见正面镜。同一三折镜中央面若始终可见，翼面可能一直落选。合同需明确可复现的面选择规则，例如保持当前单目标规则并用镜头只纳入目标翼面，或给现有观看入口一个明确的优先面选择（纯显示策略）。不能把轮流更新三面、保留三张旧图当成同一活动目标预算。主代理需在小样阶段解决此点，然后固定四款共同适用的选择语义。

官方 Reflector 支持平面真实反射及目标分辨率/采样控制，本地 r187 基于自身 matrixWorld 的位置与 +Z 法向构造虚拟相机和斜裁剪面。上述方案只做有限平面坐标适配与 owner 列表扩展，继续调用原 Reflector，不重写反射算法。来源 https://threejs.org/docs/pages/Reflector.html 与 https://github.com/mrdoob/three.js/blob/r187/examples/jsm/objects/Reflector.js

六、实际补光、状态与共用预算

建议每台镜只创建一个实际 SpotLight，固定有厚度的上沿灯罩和扩散条均包含该实际出光点。候选灯源为镜局部 [0,.585,.065]、目标 [0,.43,.72]，方向向 +Z 并略向下，位于反射头部上方，不从镜背向墙照。目标转入桌面局部约 Z=.585（采用镜 Z=-.135），Y=1.21m；该点只用于有限照明方向，不证明真实男女脸部已适配。

候选 light.kind=spot、color=#fff4df、distance=1.5m、angle=.55rad、penumbra=.6、decay=2、castShadow=false。所有四款实际灯位、目标、颜色与范围相同，灯罩可改变外围结构但出光点始终位于真实扩散孔。建议 stateDefaults={on:true,intensity:5}，stateSchema.on boolean，intensity number [0,10]，stateSemantics 分别明确局部补光开关和 candela 强度。此强度为沿既有 fill-light 的初始候选，未作光度或屏幕效果验证，不能写成达到化妆照度标准。

候选将 on 解释为灯开关，关灯后镜面仍反射，intensity=0 同样不输出实际局部光。branches 的 reflective-on-off 字符串须由新合同明确采用此语义，若主代理要求独立关闭反射，则再给 reflectionOn 独立 boolean 并接入 controller eligible，不把灯灭误当反射功能已关闭。本包建议固定暖白色参数并真实驱动 Three.Color，不声明可调色温。如果主代理选择色温能力，需增加有界数字状态与固定转换/颜色空间定义、实际 RGB 变化及保存证据，当前 fill-light 没有这条动态链。

当前 display.screen 的 onIntensity 固定，改变 intensity 只改变实际 SpotLight，发光材质强度不会同步渐变。若新款承诺调光同时改变可见灯罩，需为新镜灯明确受限映射，不改变旧屏幕字段语义。无论是否调灯罩，关灯和调 intensity 的证明都必须来自受光物体实际像素或同镜头可观察光照差异，灯罩自身变亮不足以证明场景受光。

SpotLight 现有 position/target/range/angle 路径可直接复用。PointLight 向所有方向发光，当前 renderer 没有按 kind 分派，无须本包新增点光路径来完成前向台镜补光。SpotLight target 必须随光源加入场景并跟随同一父变换，沿目前设施 root 挂载即可。来源 https://threejs.org/docs/pages/SpotLight.html 与 https://threejs.org/docs/pages/PointLight.html

公司 createCompanyScene 默认 maxRealtimeLights=2，applyPresentation 在所聚焦房间内按稳定 id 选 desired>0 的前两盏，关灯者不占活动名额。台镜灯应加入同一 lights 列表，与既有 fill-light 共用两个名额，不每台另开预算或给每个外观独享实时灯。补光关掉后须证明后排候选能进入名额，第三盏应明确显示受预算抑制而非保存状态被改成 off。保留 state on 与当前实际 enabled 的区别。

局部灯仍 castShadow=false，不新增局部阴影 target/pass。当前预览宿主另有 HemisphereLight 和一个 1024² DirectionalLight 阴影，sun 在单房/room 聚焦才启阴影。台镜不顺带提高阴影分辨率，也不把“场景开了阴影”写成台镜有遮挡阴影。无阴影 SpotLight 可能穿过薄墙照到近邻表面，有限 distance 与房间聚焦缩小影响，实际跨墙限制必须如实保留。原 Reflector 更新期间复用宿主既有阴影，不为反射另算新阴影。

实时反射与 wall/floor 共用 1 个活动 owner、≤30Hz、每主帧一次，沿能力检测选宿主 profile。旧+候选 preflight 交接允许目标峰值 2，仍不能同帧叠加三折各面的常态 pass。补光参与主场景和反射场景的真实受光，反射预热须在候选实际灯和预算已经应用的状态下执行。对象数/逻辑名额与实际 GPU shader/绘制成本需分别记录。

七、需要主代理锁定的跨模块增量

1 将 vanity-surface 用途适配到 support-surface 及严格 vanity-table/top 父限制，锁 .70×.60×.16m 候选和实际底座/柱接口。改变 pending 候选尺寸要更新具名目录及新合同，不修改已验化妆台支持面来凑通过。

3 增补新镜 light 的有限值、固定位置/target、灯罩节点和实际出光点准入，将其照明字段纳入功能比较。可只对新分支收紧，若同时收紧旧 fill-light 比较需做受影响兼容回归，不能无证扩张本包修复范围。
4 明确 on 的灯语义、反射是否独立关闭、固定暖白与是否需可调色温，以及 intensity 对灯罩的显示映射。状态沿既有数值/boolean schema，保存沿旧公司 envelope，不另建反射截图或灯光状态文件。

这些为主代理内部技术合同选择，已有授权允许有界实施，无需用户逐项决定技术数值。本文提出具体接口缺口，没有据此生产或修改运行实现。

八、最小制作、运行与恢复验收

先做圆镜和真实折角三折镜核心小样，实际回读分别核共同底座接触、柱与曲背板相交、每面世界法向、轮廓/厚度/遮挡和完整安装包络。再完成带灯镜、拱镜，四款结构真实不同。每件候选先约束 ≤2500 三角、≤32mesh、≤4 材质，无纹理也可完成本包；若真实框灯结构超预算，先定位实际构件成本，不能降低几何准入。

统一制作输入沿已有参数化生产器结构，记录用途/规格/方向/基点/承载/留空/状态/节点/材质/预算/来源。import 无写入，--check 不依赖 evidence，重复导出逐字节一致。至少一款实际修改框宽或底座宽的允许参数重导出，经真实 GLTFLoader/新几何门后登记，另三款 GLB 字节不变。固定合同、源、生产器、依赖、验证器与模型 SHA 均进入输出，保失败源/网格/错误和回滚点。

输入 A 使用当前一房化妆台与正确配对椅，替换掉与台镜冲突的后部数字钟。输入 B 使用另一房和独立台镜/台体 ID，父台 yaw=π/2，子镜 local yaw=0，设不同非默认灯强度/on。两输入共用生产/登记/配置/apply 入口，四款普通换款保台体和子镜身份、attachment、局部变换、灯状态及其他子物状态。移动父台时镜体、每个反射面、真实灯和 target 全部随同最终变换，椅子按既有显式同事务规则移动。

实际 GPU 验收以非对称、主相机屏幕外但反射相机可见的活动宿主物验证真实反射，中央/三折两翼逐面验证法向和视差。用前方已存在非角色物体的同材质受光区核灯开/关、强度变化和实际颜色参数，保持相机/曝光/ambient 相同，不能只比较发光灯罩。角色、男女脸位置/手部动作和真实受光留 C3。

混合 wall/floor/makeup 镜及 fill-light/镜灯验证一反射目标/两实时灯名额，隐藏、切层、building、聚焦另一房时实际停用并释放。重复换款、切层、丢弃候选和 dispose 检查目标/几何/材质归属及稳定回收。当前/候选 preflight 的目标峰值和反射 pass 单列，实际画质档/采样/颜色深度格式可查。记录主pass/反射calls、triangles、CPU submission 和测试设备，普通电脑无证据就保未测。

坏例应覆盖薄片假底座、断开的柱/圆背板、悬空翼/灯、框遮镜、侧翼错误法向、伪造共面、完整包络越界、错误父/surfaceId、与钟/收纳重叠、子镜错误90°、过高、非法光参数/NaN/零方向/未知状态/越界强度、改变光向的“兼容”替换、缺节点/坏 GLB/版本与依赖错配。每种沿事务拒绝且旧文档、场景和已保存字节保持原值。

四款分别保存并关闭浏览器进程重开，检查最终资源版本/节点身份/attachment/父子变换/非默认灯状态。恢复后的反射必须从当前场景新绘制，无旧层像素或旧目标。坏 shader/FBO/未知 render 异常沿既有失败保旧与宿主 renderer 重建路线验，不能把 JS 公共状态恢复声称 GPU 私有栈已修复。最后从确切独立检出构建、完整锁依赖离线重建、同版本正常1×录像并交用户观看。

尝试预算为一次有依据实现，加一轮有真实失败证据的修正。同根因两轮无新证据或改善时重新定位，保原失败，不用静态图/共面改名/只发光材质降低反射或照明标准。
