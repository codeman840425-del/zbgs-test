3. “完整”的定义

完整是调研范围内各类功能都有 agent 可执行的真实路径，并能在明确的素材标准、身体范围和兼容规则内重复生产、组合与恢复。不能只登记字段、写接口、挂菜单或展示一张图就算支持。

不要求把所有发型、服装款式各做一遍。相同技术机制可以共享流程；每种独立机制必须有具备相应结构的实际样件和运行证据。

技术样件可以简单，但不能用静态挂点代替真实蒙皮，用短发代替长发动态，用单件穿上代替叠穿验证。

把调研的全部功能逐项映射到 CAPABILITIES.md，写明现状、实际入口、适用资源及参数范围、依赖、证据和剩余工作。它仍是唯一能力状态清单，计划只引用它。

未实现、未接入、未验证分别记录。不能以“暂不支持”静默移出本次完整目标。确实无法落实的项目，提出原因、实际替代方案和影响，由我明确同意变更后才能调整完成范围。

4. 必须覆盖的自定义功能

人物基础与身体

男女分别适配；身份性别、身体基础、年龄数值、年龄外观、造型偏好和行为风格分开。

支持身高、头身及躯干四肢比例、体积与肌肉的独立变化，覆盖颈、肩、胸廓及胸部软组织、腰、腹、骨盆、臀、躯干长度、上臂与前臂、大腿与小腿、手掌与手指、足与踝。长期体态放在行为或姿态层。

年龄外观的轮廓、软组织和表面细节有实际制作路径；需要独立基模的年龄或比例类别，按独立基模接入适配，不能用整体缩放冒充。男女不能互相套参数宣称都通过。

头脸与五官

覆盖头宽高深、颅顶与后脑、面长宽、额与太阳穴、颧骨、面颊、下颌、下巴及正侧轮廓。

眉、眼、鼻、嘴、耳分别支持适用的位置、比例和形状修改，包括：
- 眉高、间距与眉形。
- 眼距、高低、深度、眼裂、眼角、眼睑。
- 眼球位置与大小、虹膜比例。
- 鼻根、鼻梁、鼻尖、鼻翼和鼻孔。
- 嘴位、宽度、上下唇、唇峰、嘴角、人中。
- 耳大小、位置、外展、耳廓与耳垂。
- 五官相对布局及上中下脸比例。
独立变化不能被永久捆成一个混合端点。建立明确的部位、侧别、局部坐标与单位；对称和按侧别修改有明确语义。数值变化必须作用于实际几何，表达 morph 不能冒充永久容貌。

肤色与表面

肤色明度、底色、饱和度分别管理，保持身脸一致。虹膜、发色、眉色、胡须色、外唇色可以独立管理，并可按配置联动。

痣、雀斑、疤痕、局部色差、年龄纹理支持部位、位置、大小、浓淡等适用参数。保护眼白、瞳孔、高光、口腔和非目标区域。

毛发

覆盖光头与贴头、短披发、中短披发、长披发、半束、马尾、盘发、编绞发及特殊结构的接入方式；支持刘海、分缝、发际、密度与体积、发色分区及独立发饰。

落实刚性、蒙皮、附加骨动态等实际需要的机制，以及帽发共存、遮挡与卸下恢复。

自然眉、胡须、体毛分别管理，眉与胡须随面部变化和表达正常工作。每种款式不必全部新制，但不同技术机制不能漏验。

妆容

覆盖眉妆、眼影、眼线、睫毛、美瞳外观、唇妆、腮红、修容、面部图案、身体图案和美甲。

款式与纹理，同颜色、浓度、覆盖范围等适用参数分开。明确层次、遮罩、替换和卸载恢复。睫毛、指甲等需要几何的不能只用颜色字段替代；几何五官与化妆分别保存。

衣服与鞋袜

上装、裤裙下装、连体装、外套、贴身层、袜和鞋均有实际接入路径。

支持槽位占用与冲突、声明兼容的叠穿、身体与衣层遮挡及完整恢复、材质与分区配色。

同款面对不同身体保留 styleId，使用独立版型、权重和适配数据，不以整体缩放代替适配。

长裙、宽松外套、披肩等需要形变或动态的结构，要落实相应资产配置与验证。鞋类覆盖平底、靴及带跟、厚底所需的鞋楦、脚姿、落脚高度、步态和座位适配。不能沿旧“仅平底”“固定上衣鞋”的限制宣称本轮完整。

配饰与功能道具

覆盖头、面、耳、颈、胸、背、腰、手腕、手指、足踝的挂接、蒙皮与适用动态；左、右、成对及同部位多件的规则明确。

落实帽子、眼镜、耳饰、项链、围巾、胸针、背包、腰带、腕饰、戒指、脚链、携带物等技术类型。

功能持物覆盖单手、双手、握姿、使用端、目标位置和动作兼容。麦克风、商品、杯、乐器等依其真实用途验证。复杂功能物须有匹配用途的代表动作，不能仅挂在手上称会使用；完整才艺内容库和经营玩法留到游戏制作。

造型与组合

身体、固定容貌、毛发、妆容、衣服、配饰可单独修改、复位、替换、组合并保存整套方案。

分类标签用于 agent 检索与匹配，不直接决定兼容。支持从已有方案派生新方案、恢复已保存版本；不能改一个人的外观影响另一个人。

上述字段可通过离线制作、受限参数、资源变体或配方实现，不强制全部做成浏览器实时滑条。每项选择可靠、可复现的实现方式，并说明连续范围、离散选择与约束；不能把未验证区间自动开放。

5. 补齐共同机制，避免逐件修控制器

沿现有加载器、装备、表达和动作模块增量完善。将固定服装组合补为配置驱动的装备选择、占用互斥、覆盖集合与恢复；发型和配饰遵循同一身份、版本、适配和生命周期原则。

面部修改同时处理眼球、眼睑、睫毛、眉部表达、牙齿、口腔、口型、眼镜、耳饰、发际及麦克风目标。身体修改联查衣物、手持、步幅、脚底、座位和相机框定。

必要的权重、版型、挂点、姿态或动态修正，由 agent 制作并保存为可重复生成的资产及适配数据。

普通新增素材必须沿标准源、配置和适配流程接入。发现共同缺陷修一次共用机制；不能为每件普通衣服往通用走路、坐姿代码增加名字特例。特殊结构允许专用资产配置，但需要明确输入、限制和再生成方式。

允许动作连贯前提下轻微穿模；明显裂面、错位、跳姿、持续滑步、严重穿插和错误持物仍应处理。

6. 建成 agent 可执行的生产流程

复用既有脚本和工具，形成实际可执行的流程：

输入检查 → 制作与适配 → 导出 → 登记与校验 → 加载 → 受影响验证 → 交付。

命令索引只是入口说明，不能代替实际生产能力；也不必新造通用编排器、完整 MCP 系统或大型 API 服务。

每条流程明确输入文件、参数、前置工具、可编辑源、来源许可、输出目录、资源与适配版本、退出状态、结构化错误及恢复方式。

区分只读检查、实际生成和正式登记。新任务使用独立输出，不覆盖已验资源和历史证据；失败不能留下一半新资源冒充成功。

至少用独立的新标准素材或新的有效配置完成重复生产验收，证明不是只能重放某次样板。所需技术素材由 agent 寻找或制作，不交给我修模。无需每个款式重做同类测试，按实际依赖选择检查。

专业参数由 agent 通过制作入口操作。可以自动生成对照图和录像，不为每项功能新增交互面板。

不建设完整人工捏脸编辑器、衣橱商城、分类筛选大页面、预设管理后台、招聘或档案前端，也不反复美化现有页面。已有可用界面保留，不为“精简”再拆重做。正式玩家界面按后续游戏需求建设。

9. 推进顺序与迭代纪律

先完成当前交付及生产入口补齐，随后建立全部功能到实际技术机制的缺口映射。按依赖推进：
1. 共同数据、装备组合和资产接入机制。
2. 外观、身体、毛发妆容、服装鞋袜和配饰的缺失能力及适配。
3. 确定性多角色记录、共用游戏消费和统一候选验收。
可独立工作按能力分工，避免同一源码、GPU 和录制任务冲突。

每个工作包先写清真实缺口、所需最小样件、实际验收、影响和回滚点。已有证据有效则复用；修改后只补受影响回归，不机械重跑所有历史检查。

先复用已验证、许可明确的工具和算法。连续尝试没有新增证据或实质改善时，停止同方向扫参，检查共同原因并比较可执行替代路线。

不得靠不断加姿势补偿、放宽检查、扩大数值或重录同一片段凑进度。失败项保留，不能推给 M3 后宣布 M2 结束。

10. 实际验证与固定交付

每种独立机制验证真实输入输出、实际几何或材质变化、保护区域、源导出、运行加载、组合边界及保存恢复。

保持绑定和表情，按影响范围实际运行眨眼、注视、口型、情绪、走跑转向、坐起、持物及舞蹈代表动作。检查完整过程；数值通过、无报错、抽帧正常不能代替完整动作质量结论。

通过坏版本、不兼容适配、缺源或缺资源等实际失败用例，验证保原、明确拒绝、已声明回退和可重试。不得悄悄换身体或改变外观。

多实例核查可变几何、材质、装备、表达和任务隔离，资源释放有实际检查。

最终候选从确切提交的独立检出构建，源、资源、配方、观看入口和录像版本一致；有恢复与远端备份核验。

正常速度证据保留，技术正确性、工程视觉检查、用户最终验收分别说明。普通电脑未测如实保留，开发机不代替目标设备；外部条件缺口不得阻止其他独立工作，也不能被记成通过。

M2 交付应使后续标准素材扩充主要成为 agent 执行制作、适配和验证任务，而不是每新增一件就补一次通用框架。
