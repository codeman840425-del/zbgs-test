公司场景与设施 agent 创作平台——连续建设长目标 v2\
\
你继续担任公司场景与设施平台副总工，按本指令持续完成整个平台。\
\
本指令替换上一版长目标的实施顺序和协作方式。最新版 F:/gamemake/docs/COMPANY-PLATFORM-DEPUTY-BRIEF.txt 中已经确认的功能范围继续保留；将其中与本指令冲突的阶段安排同步修改，不删减最终能力。\
\
保留第一包及已经完成的组件、组合、实例、编辑和保存代码，按真实可用程度继续建设，不因调整顺序推倒重做。\
\
一、最终目标\
\
完成一套让 agent 能根据美术素材和配置，持续制作不同公司空间与设施成果的可用系统。\
\
完整流程：\
用户提出想法 → agent选材、制作和适配 → 组件组合与布局配置 → 检查与预览 → 修改 → 批量生成 → 保存、导出 → 统一接入游戏角色系统。\
\
平台主要供agent使用，人类负责方向和观看验收。技术制作、修模、对齐、配置和排障由agent完成。\
\
当前首先解决：\
\- 素材能接入和替换。\
\- 组件能组合、拆分和复用。\
\- 布局能自定义。\
\- 同一流程能批量生成不同成果。\
\- 成果能保存、继续修改和独立移交。\
\
初期不要求逐项播放人物动作。场景和设施生产能力形成完整成果后，再集中接入角色并验证实际使用。\
\
二、职责与协作方式\
\
你负责空间、设施、装饰、组合、素材接入、布局编辑、批量生产、预览、保存和导出。\
\
总工继续专注角色系统，负责人物移动、动作、身体适配及最终共享运行集成。\
\
沿已经确认的技术路线、接口和工作树边界独立推进。日常实现、选材和内部排障由你处理，不频繁向总工派发小任务或要求确认。\
\
现在根据已确认接口保留必要数据，把接口疑问和缺口集中记录。有可观看、可复用的阶段成果后，再集中与总工对接。确实无法独立推进的兼容性阻碍集中说明，其余任务继续。\
\
不得另建角色控制器、动画时钟或正式角色占用状态机。场景预览可以暂不加载人物，尺寸标记和使用点可视化仅用于检查，不能冒充角色实际通过。\
\
阶段完成后继续下一阶段，不自动停工等待用户批准。\
\
三、C1：完成素材、组件、组合与自定义布局能力\
\
目标：agent能够接入真实素材，组合设施，修改场景，并得到可观看、可保存的成果。\
\
1\. 素材接入与标准化\
支持已经规划的建筑模块、家具、设备和装饰素材。\
记录来源、许可、可编辑源、工具版本、资源身份和依赖。\
明确尺寸、单位、朝向、基点、材质、贴图、承载面及安装位置。\
不兼容素材给出具体原因和适配步骤，由agent处理。\
\
真实新素材接入在本阶段完成，不能一直只操作原来的灰盒，最后才尝试换模型。\
\
2\. 外观与功能分离\
设施类型和功能数据，与模型、材质、配色及外观版本分开。\
普通换外观保留设施实例身份；新模型尺寸或结构影响使用时，更新适配信息。\
不能仅凭同名或同类型就认定任意模型可以直接替换。\
\
3\. 组件与组合设施\
落实整套直播工位：\
桌子、椅子、显示器、键盘、桌面麦克风及补光系统。\
\
支持整体移动、旋转、复制，部件局部调整和兼容替换。\
桌面设备跟随桌子；整个工位变化时内部关系保持。\
多个同款实例具有独立身份、配置和状态。\
更换承载物时检查安装关系，避免设备悬空或沿用错误偏移。\
\
4\. 自定义布局\
agent通过脚本和结构化数据创建、放置、移动、旋转、替换和删除设施。\
支持房间、公共区域、建筑模块、独立物件和组合工位的配置。\
明确允许的形状、尺寸、旋转和缩放范围，不承诺未验证的任意变换。\
\
视觉网格、导航阻挡和接触形状可以不同，但必须共享正确的实例变换，避免分别维护互相漂移的位置。\
\
5\. 提前保留交互所需数据\
现在就提供接近点、使用点、朝向、接触面、离开空间、使用限制和容量。\
完成数据一致性、空间尺寸、摆放、依附和通路的静态检查。\
真实人物的可达性、接触、坐起和占用正确性，留到C3统一验证。\
\
6\. 四类设施的生产与显示基础\
覆盖静态装饰、简单动态物件、单人交互设施、多使用点设施。\
当前检查模型、配置、独立使用点、显示状态及保存。\
灯光和屏幕状态必须在预览中实际生效；角色受光和实际设施使用在C3核查。\
\
7\. 场景预览与基础保存\
提供简洁的加载、方案切换、视角查看和状态演示入口。\
保存完整布局、组件关系、局部调整、设施状态及资源版本。\
关闭重开后能继续修改，不要求重新手工对齐。\
不建设复杂人工装修编辑器。\
\
C1的交付应让用户直接看到：\
替换素材、组合复制、整体和局部修改、自定义布局以及保存恢复。\
真实角色活动不是C1的前置条件。\
\
四、C2：完成四档公司规模与批量生产\
\
统一层级：\
公司 → 楼层 → 房间 → 工位 → 工位部件。\
\
房间可以有独立家具和装饰，楼层可以有公共区域，不强迫所有物件归属工位。\
\
四档配置：\
\- 单间屋：1间经营房间，最多2个直播工位。\
\- 整套出租屋：3间经营房间，最多6个直播工位。\
\- 整租平层：10间经营房间，最多20个直播工位。\
\- 整栋大楼：5层、50间经营房间，最多100个直播工位。\
\
公共通道等另计。工位数量是全部房间用于直播时的理论上限，实际数量由用途和配置决定。\
\
本阶段完成：\
\
1\. 同一套机制生成四档规模\
房间、门口、通道和连接关系可配置。\
空间连接和静态通行规则真实成立，不只在图像上相通。\
四档共用素材和运行模块，不分别编写四套场景程序。\
\
2\. 观看与楼层切换\
实现单间近景、整屋剖面、平层总览、房间聚焦、大楼概览及楼层选择。\
墙顶遮挡处理只影响观看，不改变实际阻挡或设施数据。\
切换观看楼层与角色跨楼层移动分开。\
真实上下楼、连续乘电梯动画不自动纳入当前范围。\
\
3\. 批量生成不同成果\
agent可以提供多份明确的素材选择、组合和布局配置，批量生成独立产物。\
每份产物有明确身份、输入和资源版本，能够重复生成。\
某份失败应能定位并单独重试，不覆盖其他有效结果。\
保存最终结果，不能只留下随机种子或脚本路径。\
\
代表成果应实际体现素材替换、组合或布局变化，不能只复制同一场景换名称。\
用少量样件覆盖机制，不扩成大量美术款式制作。\
\
4\. 完整保存与版本管理\
保存全部楼层、房间、设施和组合，而非只保存当前可见部分。\
同名房间和同款工位不串用身份或配置。\
模板更新默认不改变已保存公司；显式升级时保留兼容的局部调整，不兼容则说明原因并保旧。\
缺资源、错误版本或变更失败不能提交半套场景。\
\
5\. 资源成本与移交\
按需加载和释放显示资源，明确远处及其他楼层的简化方式。\
在代表场景中确定多工位补光和阴影预算，不随工位数量无上限叠加高成本灯光。\
产物能脱离制作目录加载、预览和恢复，并保留继续编辑所需的源和配置。\
\
C2结束时，应形成完整可用的场景与设施创作成果。\
角色实际使用尚未验证的部分保持明确标注，不因预览成功而提前宣布联调通过。\
\
五、C3：集中接入真实角色，完成平台整体验收\
\
C1、C2形成完整成果后，再集中与总工对接。\
\
一次整理：\
\- 固定场景源码、资源和配置版本。\
\- 已有设施接口与使用点数据。\
\- 需要角色系统消费的输入及返回状态。\
\- 确认存在的接口缺口和复现样例。\
\- 建议集成范围及受影响验证。\
\
由总工负责共享角色模块和最终集成，你负责场景、设施及适配修复。\
在同一个固定候选上集中验证：\
\
\- 真实男女接近、使用、离开单人设施。\
\- 两个工位及多使用点的独立使用。\
\- 同位置争用、取消、失败、实际离位和资源清理。\
\- 不同位置和朝向下的导航、姿态及接触。\
\- 忙碌设施的修改规则和失败保旧。\
\- 观看切换不改变角色归属、任务及占用事实。\
\- 保存重开后的布局、身份和有效状态恢复。\
\- 真实角色材质下的补光效果。\
\- 新素材或新布局沿同一流程接入。\
\
不要求每份批量产物都重复完整角色矩阵；按变化和风险选择代表，复用有效证据。\
\
角色接口问题由总工修复，设施数据或适配问题由你修复。\
完成实际联调后，才能声明整个公司场景与设施平台具备游戏使用能力。\
\
六、最终交付标准\
\
第一版必须实际证明：\
\- agent能够接入新的合规素材。\
\- 能修改组件、组合和布局，不反复改通用代码。\
\- 能批量生成不同且可继续编辑的公司成果。\
\- 四档公司规模由同一套层级和配置机制表达。\
\- 全部布局和版本能够保存、恢复、导出和独立加载。\
\- 真实角色已在代表设施和布局中完成统一联调。\
\- 新输入能够重复走通生产流程。\
\
交付包括agent入口与示例、素材规范、可编辑源、配置与版本规则、实际产物、简洁预览、失败恢复方法、固定构建及备份。\
\
沿现有CAPABILITIES记录实际能力，不另建矛盾台账。\
区分“生产与预览已通过”“角色接入未验证”“角色联调已通过”“用户观感已验收”。\
\
七、效率与持续推进\
\
\- 内部可以拆小任务，但不将每个提交或检查变成人类审批节点。\
\- 新要求改变顺序时保留已有有效实现，不重启项目。\
\- 当前优先完成生产能力，不被逐件人物动画验证牵制。\
\- 使用已确认接口独立工作，有阶段成果后集中对接总工。\
\- 优先复用成熟工具和许可明确的素材，不另造通用引擎或编排平台。\
\- 独立制作、数据处理、实现和审查按AGENTS合理并行。\
\- 普通功能检查可协调并行，只有需要可比较测量或重型录制时安排必要窗口。\
\- 仅验证新增或受影响内容，成功且未变化的检查不反复运行。\
\- 同一根因连续两轮没有新证据或改善，停止扫参，重新定位或采用替代方法。\
\- 严重错误、错误身份、错误占用和数据丢失必须解决；装饰细节及无收益调参不拖住主线。\
\- 汇报新增创作能力、可观看成果、真实限制及下一步，不用测试数量或文档篇幅代替进度。\
\- 阶段汇报后继续，直到完整第一版提交整体验收；真实费用、授权、重大产品选择或无法独立解决的阻碍集中说明。\
\

\

普通电脑性能、批量生产效率、错误提示、观看和灯光效果，以及经确认的素材款式扩充。\
\
必需功能不得偷偷移到优化阶段。\
租金、招聘、收益、交易、PK、服务器和玩家装修玩法保持后续业务范围。\
\
现在同步修正简报和执行顺序，继续完成场景与设施创作系统。优先交出能换素材、能组合、能自定义布局、能批量生成和保存的实际成果，随后集中接入角色验收。
