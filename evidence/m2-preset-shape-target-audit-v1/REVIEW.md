# 预设形状目标审查：尖锥脸来自目标，不是残差

**当前 male lean 不应作为正常可用预设。** 已查看 root 在 4196 的实际截图 `output/playwright/preset-triage/male-long-lean-axial-head-v1.png`：下颌向口下收成细长尖锥，眼区与上脸保持原宽。该观感有目标及已保存几何的直接解释；继续逼近原 101 并不能修正它。本包只读，没有新形状/曲线/导出。

## 确证原因与授权边界

1. `m2-representative-batch-v1/spec.json` 的 male-long-lean 参数进入 v2 时逐项不变，v2 `build.py:107` 甚至要求相等。原值是 jawWidth=−.20、cheekWidth=−.14、chinLengthM=.014、chinProjectionM=.004。未发现这些精确数值来自用户。用户完整 v2 第 1 节明确不为远景差异反复扩大参数；第 4 节要求上中下脸、五官相对布局及独立语义。
2. `scripts/m2-representative-head-cage-v1/head.py:194` 起把源 101 截面边界点按 `x'=Hx+(x−Hx)(1−.20 jaw(y)−.14 cheek(y))`、`y'=y−.014 chin(y)`、`z'=z−.004 chin(y)` 制成请求。jaw 与 cheek **相加**；实读最窄比例 0.669216，约收窄 33.1%，并非两个标签只取较强者。chin 的过渡限在 face_lo 至 mouthMin，嘴以上没有对应的向下布局移动。
3. 保存的实际 lean 几何中，脸最低点下降 14 mm；Mouth 材质最大 Y 变化仅 0.000166 mm。Mouth 最低点到 skin 最低点距离从 32.455 mm 增到 46.455 mm，增加 **43.14%**。这是材质包围盒量，不冒充解剖唇点测量。眼 Iris/White/Highlight、眉的 base 精确不动；口横向最多移动 8.880 mm。鼻没有独立语义标签，不能声称“整个鼻固定”：公式只保证 mouthMin 以上 dY/h=0，x 仍随层缩放。
4. 所以它同时发生下脸横向收窄、口下区域纵向拉长、颏前移，而没有正常整脸比例设计。源 101 范围只有 head-local Y≈[−49.208,29.715] mm；其数值门主要描述下脸包络，没有眼间距相对脸宽、口颏比例、侧面颏转折、颅顶比例或作者设计参照。严格 J/接触/身份检查能拒技术坏例，不能判断一个无翻折的尖锥脸是否正常。
5. 后来 PCHIP G 忠实实现了这些请求；一级细分把 lean 101 误差从 .825 mm 降到 .182 mm，但没有改变请求。这里是**把实现自产的代理目标提升成产品不可变要求**的失误，不应再归因求解不够强、采样不够密。

用户要求的是可持续制作、正常绑定/表达/适配和最终可观看验收。101/2 mm、眼源坐标 2 µm、14 mm 颏长和四参数范围均是具体实验合同，不能默认为永久产品风格。原失败合同必须封存；未来改变目标或允许五官布局适配，要有新 recipe/身份/验收，不能给旧失败改标签。女性宽腰/衣鼓包在本包仅收到截图定位，未独立数值审查，不能套用本头脸根因。

## 已有资产与成熟作者路径

项目当前男女是旧 beta 0.14.0 的第三方 VRM 导出，已有合法性记录、可编辑重建 `.blend`，**没有原 `.vroid` 工程**；本轮在项目相关资产/工具清单未找到 `.vroid`，也未验证本机可用 VRoid 编辑器。`foundation-male/source.json` 与 `LICENSE.md` 已诚实保留第三方来源和未与官方 beta 导出逐点核对的边界。官方旧 [New model](https://vroid.pixiv.help/hc/en-us/articles/900000088126-New-model) 仍明确该旧模型 CC0，不能推及新模型。

原作者现成可编辑机制是 VRoid 原生 Face Sets / Eye Sets 与部位参数：Eye Set 把虹膜、高光、眼白、眼线、睫毛作为关联集合，并有鼻、嘴、口内、面颊和表达编辑。比“只量下脸横截面、其余锁死”更符合本次缺口。[官方脸部编辑](https://vroid.pixiv.help/hc/en-us/articles/4406164546969-How-to-edit-faces)；[官方表达编辑](https://vroid.pixiv.help/hc/en-us/articles/4408150140825-How-to-use-the-Expression-Editor)。文档证明功能存在，不证明自动无接触或本项目已接入。

现 VRM 不能恢复原生参数；官方明确脸部再编辑需 `.vroid`，VRM 可交 Blender/UniVRM。新 VRoid 的服装导入能力也不能当成旧头脸参数恢复。[文件能力](https://vroid.pixiv.help/hc/en-us/articles/360020275314-How-to-edit-a-VRM-file-Can-I-re-edit-a-VRM-file-in-VRoid-Studio)、[导出与表达保留](https://vroid.pixiv.help/hc/en-us/articles/15760756822297-I-want-to-learn-more-about-the-VRM-export-feature)。未核到可供本工程直接调用的官方无界面参数 API，不应再把界面按钮写成现成批处理接口。

许可边界：新默认基模并非 CC0；官方允许无特别限制的内容商用、离线修改，另对模型生成应用规定许可并列出仅自己使用的例外。当前应限定内部制作后向游戏交付固定资源，不据此承诺对外造人服务。A–Z 样例另有禁止用于造人服务等条件，不能替换成 CC0 标识。本建议优先**新建默认工程**，不混入 A–Z 或第三方付费内容。[Studio guidelines](https://vroid.com/en/studio/guidelines)、[A–Z 样例条款](https://vroid.pixiv.help/hc/en-us/articles/4402394424089-VRoidPreset-A-Z)。本次仅核官方文本，没有采购或取得额外授权。

## 唯一最小制作替代建议

**下一包先做一个“作者原生整脸设计→可观看候选”的 male 瘦长方向样件，不再改原四参数幅度。** 在官方编辑器新建可保存的男性 `.vroid`，保默认身体/衣装，使用一套作者预置 Face Set 作完整脸部起点；agent 记录其真实选择与参数，由部位编辑形成正常窄长方向，连同眼鼻口/下颌关系一起审正面、侧面、3/4。不要求用户操作，也不承诺仅套 Face Set 就自动达到风格或通过游戏。若有已合法且确切可编辑的同源工程优先复用；现旧 VRM 不伪称能回灌。

这是一条新的**源制作候选**，不是给旧源贴新目标或偷偷换已选角色。先交原源与新源的同镜头静态图、neutral/blink/happy/五元音及 known-oh 短片，工程视觉必须先排除尖锥/怪异比例；通过后才作一次 VRM 导出并建立新 sourceSHA/骨架/表达/材质/装备契约，复用当前游戏加载器而非换引擎。新源不要求仍有旧 54 个内部 morph；必须完整保真实源并逐一核 VRM 预设语义，不能借旧 55 通过。旧衣物适配、旧 profile、旧101均不得继承。

预算建议：一次编辑器可用性/默认工程保存/许可身份检查≤30分钟；若不能通过则停在明确工具阻断，不逆向 `.vroid`。随后只做一个作者脸部候选，制作与三视检查≤60分钟，最多一次导出；不批量八体、不搜索滑条网格、不调 collision epsilon。若整脸仍明显失衡，停止该候选并定位实际部件控制缺口，不以精确101通过交差。上述预算是待 root 授权的制作包，**本包没有执行**。

共同 G、J/法线传输、Float32读回、源身份、共同细分和接触诊断仍可复用于有适当目标的受限几何修改；它们不是脸型设计器，也不具备 eye/nose/mouth 独立布局或源模型表达再创作。它们不应成为正常预设必须沿用旧四参数目标的理由。当前截图的怪异轮廓应按产品缺陷处理，而非再作为“技术上通过”的生产预设。

机器证据：本目录 `readback.py` / `result.json`，只读取原参数、原101、已保存实际G端点；无新变形。原图及关键输入 SHA 均在 result。
