# D02 角色制作入口独立审查

2026-11-17，Windows、Node.js v24.13.0。修复了制作输出可能被自身证据覆盖，以及输出发布后仍报告失败的两条路径。

| 情况 | 复验结果 |
| --- | --- |
| 输出路径与证据冲突 | 两个入口先解析已存在父目录及 junction，再检查最终路径。CPU 测试覆盖 Windows 大小写、尚未创建的中间目录、目录本身和带尾点的歧义路径。 |
| 成功发布 | 浏览器任务先完成验证、录像与截图（指定 evidence 时），关闭浏览器并写证据报告，再通过现有排他写入器发布最终 JSON。成功时仅有一份成功回执。 |
| 浏览器关闭故障 | 注入 close 异常后，任务返回一次失败回执，最终输出路径空缺。 |
| 证据报告写入故障 | 模拟 report.json 不可写，最终输出路径空缺，任务返回一次失败回执。 |
| 最终发布与其他写入者冲突 | 模拟另一个写入者先占用输出路径，得到一次 output-conflict 回执，原有字节完整保留。 |

证据报告的 `validated-before-publication` 表示验证和浏览器清理已完成。最终输出是否成功发布以命令行 JSON 回执为准。请求证据使用实际解析的输入字节，避免等待期间原请求文件变化。

另核到 create 缺少稳定 ID 会意外生成随机身份，以及显式 null edits 被当作空编辑序列的问题。总工已在生产模块加入显式身份与 edits 类型检查。源码中的 edit 继续使用独立候选、原记录和期望修订生成新记录，磁盘版本冲突交由既有存储流程检查；validate 先通过共用恢复链验证资源再返回输入记录。

运行 `node --test evidence/m2-production-review-v1/output.test.cjs` 和 `node --test prototype/src/character-production-query.test.mjs`，分别 5/5 通过。故障测试使用命令脚本与受控浏览器替身。真实模型制作、WebGL 和录屏另见固定构建的集成结果。
