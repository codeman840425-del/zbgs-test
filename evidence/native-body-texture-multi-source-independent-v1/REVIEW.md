# Independent native body-texture multi-source review

No new blocker was found in the bounded two-source integration. Reviewed body-texture-coverage.js SHA256 `c29a14ba222c6acde1fc9dccc60a7bc0d970f6a8c5eba4f2aa97c8ac6b5aabed` and admissions SHA256 `f97da8419cb8b98c027108291d3ff8f9362242c2273c8b183b1085dbbe9f7d37` after the author's completion notification. Exact source/evidence pins are in source-pins.json.

The immutable admission table has exactly two avatar/manifest pairs, female843ac with 003e9808 and male7586 with c432a7cd. Each actual source VRM, its embedded base PNG, corresponding masked PNG and supplied equipment catalog were read and hashed. Changing descriptor contents and recomputing its SHA does not grant admission. Wrong-sex manifests/PNGs, entry avatar/hash/slot, unknown or duplicate selected IDs, alpha and sampler mismatch are rejected. Manifest SHA fixes the material name, complete rule set and optional female sleeve rule. The helper does not itself grant garment geometry/bind fit permission.

The author's fixed core test was rerun from this independent directory, preserving its original result. It checks late PNG fetch, duplicate in-flight owner rejection, stale prepared commits, male/female instance separation and cleanup using actual Three/MToon materials. Additional independent checks cover two actors of the same sex borrowing the exact same base map and shade textures. Each gets separate owned masks, TextureSource and bitmap. Repeated disposal releases its owned texture once and preserves the other actor and borrowed textures. A staging updater failure publishes no maps and releases ownership for a successful retry.

One pre-existing API input-aliasing defect was reproduced for both sexes. After `ids=[topId]` and `p=owner.prepareEquipmentSet(ids)`, changing `ids[0]` to an unknown ID before `p.commit()` succeeds. The mask reflects the originally validated top, while getInfo reports the unknown ID in activeIds. This exact implementation also appears in the pre-change source excerpt. The minimal correction would snapshot ids before validation and use that snapshot at commit. No normal factory path that mutates this locally retained selection array was found, so this is recorded separately from the new multi-source admission result. Production code was not changed.

Runtime base texture provenance continues to rely on the avatar loader's actual VRM SHA contract. This helper checks material/sampler structure, and hashes the downloaded manifest and covered PNG. It cannot identify an arbitrary decoded base bitmap supplied by a dishonest caller. That existing boundary is explicitly documented in the source package and does not authorize other avatars or textures.

The independent fixture initially omitted the top because required belongs to manifest rules, then injected update failure on the live material instead of the staging clone. Both failed fixture versions and explanations are preserved. The corrected tests use the real required top rule and fail the returned staging clone. Neither fixture failure established a production failure.

All tests are CPU checks with substituted fetch and ImageBitmap decoding. Actual PNG bytes, VRM material JSON, samplers and pinned resource hashes were read. WebGL upload, visibility, shadows, garment fit, contact and visual acceptance were not tested. No browser, GPU, production edits, prior-evidence overwrite or Git commit was used. Requested gpt-6.1-sol/high was retained. Actual provider settings and Hook interception were not independently observable.
