UI 最终差异复核，2026-11-17

当前四个 UI 文件已经形成左侧浏览器、中央场景和右侧 inspector。公司空间与设施样件分开。公司模式左侧提供方案、楼层和房间。样件模式提供分类与组合验证入口。右侧物品、添加、装修三个页面互斥。

sample-look 只在组合工位 stream-station 场景选择中显示。普通设施从样件场景进入后，在右侧 inspector 中选择兼容外观。这个例外与当前验收脚本一致。

大楼和整层总览的入口已经收紧。building view 隐藏视图工具和 inspector 操作，显示“先选择楼层，再进入房间查看物品”。facility-editor.pointer 只在 room view 处理设施拾取、移动、复制和放置。进入房间后工具页恢复。

保存身份的上一轮风险已修正。启动恢复成功后 savedDocuments 登记当前 document JSON，save-state 会显示已保存。恢复按钮调用 session.restore()，默认使用当前 document.id。公司/样件保存和恢复按钮也有不同文案。

当前没有达到严重程度的 UI 源码缺陷。剩余工作是最终用户路径验收。qa-ui-workspace.cjs 已覆盖布局、添加、移动、旋转、原位换款、样件状态、组合场景、装修、大楼轻量视图、楼层进入、保存重启和三种窄屏宽度。

验收还应直接点击恢复按钮覆盖未保存修改，导出后导入公司和样件 document，并检查身份、父子关系、设施状态和当前视图。现有脚本覆盖重启恢复，尚未覆盖这两条操作路径。

错误字典仍有扩展空间。常见设施重叠、资产加载和外观兼容已有中文提示。profile、portal、support、state、busy、revision-conflict 可能显示通用提示。事务会保留当前有效方案，但最终 UI 需确认用户能据提示采取下一步。

company-preview:last-company 继续作为启动时最近 document 指针。恢复按钮本身按当前 document.id 工作。若产品要分别记忆公司和样件最近方案，需另行决定双指针语义。

本轮没有启动服务、浏览器或 GPU，也没有修改生产文件。runtime 和 hook 拦截未独立验证。
