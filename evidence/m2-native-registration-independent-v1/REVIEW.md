# 原生配方注册审查

两件原生 FaceContour 成品沿同一注册器进入角色目录。审查发现旧版只核配方文件自己的 SHA、未关联原生导出和游戏体之间的生产记录；第一个包写入 public 后才检查第二个包的冲突，回执也可能在目录已更新后才发现无法写入。在本次修改中，注册器一次读取实际传入的 spec 并与准备回执核 SHA，再关联原生批次、冷开后的值、实际 VRM、游戏体、三衣 ID、覆盖和地面高度。既有目标全部预检，新目标与回执先行准备。受控 I/O 失败时撤回本次新增文件，原有资源保留。

`python -B scripts/production/test_register_native_packages.py -v` 实际完成 4 项隔离测试。每个临时仓库使用两份真实游戏包、两份真实原生导出、实际 Python 资源导入器、Node 原始骨绑定检查与角色目录编译器。

|检查|实测结果|
|---|---|
|按批次选择另一个实际 spec 文件名，注册两个角色，再次同输入注册|通过；目录 mtime 及已安装资源大小/mtime 保持一致。导入器对复用资源逐文件比较字节。|
|将 A 的 sourceExport 换成 B 的 SHA、整份配方与 SHA 换成 B 的、换装备 IDs、改静止地面值、修改真实原生 VRM 字节|五种错误均拒绝，旧目录字节保留，public 没有新增包。|
|报告父目录不存在、批次末项已有不同文件|均在已有目录被更动前失败，第一包未落入 public，末项文件保持原字节。|
|两个资源均已就绪后注入 catalog 替换 I/O 失败|撤回新包和回执，目录仍为原字节。|

工作台候选取自编译后的 choices，基础角色配置从相同注册表生成，原色限制取实际登记的游戏体 SHA。审查另指出新旧 SHA 冲突需在目录编译器处理，已转主任务。以上验证针对注册与普通进程内异常。突然掉电、动作接触、画面和普通机性能仍需相应的独立证据。
