# 确定性角色批处理独立审查

2026-11-17，Node.js v24.13.0。执行 `node --test prototype/src/character-record-batch.test.mjs`，修复后七项通过。

## 修正的输入缺陷

修正前，整数组一次调用 `structuredClone`。在两份有效记录之间加入一份 provenance 误带函数的 JS 记录，构造批次会立即抛出 `DataCloneError`，阻断前后两个角色。新增回归在原实现得到六项通过、一项失败。

现按输入位置分别取得私有快照。无法取得快照的行返回 `failed / invalid-record`，保留行号和尝试号，身份、修订及摘要为空。另两份有效记录首轮各消费一次。即使调用方随后删除错误值，本批重试仍只重试原先失败的输入位置。新输入需创建新批次。

## 取消、重试与所有权

- 新用例控制 Promise 已 fulfilled、批次尚未登记 completed 的间隔。第二个消费者返回实际绑定其对象的 release，再通过先登记的 Promise 反应取消批次。最终第一项完成，第二、三项取消。只释放第二项已建对象一次，再调重试也不会重复释放。
- 既有延迟用例中，批次同步撤回当前及待处理项的资格，等待异步释放完成再结束；替代消费者保留自己已接手的对象。真实消费入口需在返回结果中携带对应实例的 release，由实例拥有者维护已完成对象。
- 同批次内的重复稳定身份全部拒绝。运行期调用 retryFailed 无法覆盖原批次。结算后只重新排队失败项，成功项的请求号、修订和摘要逐项保持一致。并行度 2 下受控异步完成顺序没有改变输入派发顺序。

测试使用归档的真实角色记录、项目的封装及摘要校验与受控 CPU 消费回调。场景挂接、真实角色销毁及关页恢复另在集成入口验证。
